# 架构

整个游戏分成三层：**模拟**决定发生了什么，**表现**决定玩家看到什么，**资产**提供模型。下层不依赖上层，所以经营规则可以完全脱离浏览器测试。

```text
assets/specs/*.json  ──►  sim.ts / navigation.ts / day.ts   （模拟：纯 TypeScript，无 DOM、无 Three.js）
                                     │ 只读状态
                                     ▼
public/assets/*.glb  ──►  view.ts / first-person.ts / sound.ts …（表现：Three.js、DOM、Web Audio）
                                     ▲
                              main.ts（游戏循环、界面、存档）
```

## 模拟层

| 模块 | 职责 |
|---|---|
| `sim.ts` | 店铺状态与规则：库存、预留、补货订单、排队、结账、升级、顾客流失原因。金额全部用整数币值计算。 |
| `navigation.ts` | 根据布局规格做路径规划和人物避让；人物用圆形近似。 |
| `day.ts` | 营业日的四个阶段（筹备 → 营业 → 收尾 → 结算）、按主题生成的逐客需求序列、结算报告、同条件重玩。 |
| `day-themes.ts` | 三个营业主题的需求参数。 |
| `admission.ts` | 顾客没能进店时记录原因：满员、入口受阻，还是正在调整布局。 |
| `comparison.ts` | 在几个固定种子上跑两套布局的对照，放在 Web Worker（`comparison-worker.ts`）里执行，不阻塞画面。 |

确定性来自三点：

- **固定时间步。** 模拟每步 0.1 秒（10 Hz），一个营业日是 1800 步，即 3 分钟。渲染帧率和倍速只改变每帧推进几步，不改变每一步的结果。
- **种子随机数。** 随机数状态也存进存档，所以读档后的客流和读档前完全一致。
- **规格驱动。** 货架容量、挂点坐标、人物半径等数值都来自 `assets/specs/`，不在代码里写死。

账目在任何时刻都满足这几条关系，测试会检查它们：

```text
现金     = 开局现金 + 销售收入 − 进货支出 − 升级支出 − 解锁支出
未售库存 = 开局库存 + 已到货 − 已售出
可售库存 = 未售库存 − 已预留
```

顾客拿起商品时，这件商品只是被预留，付款完成才算卖出。顾客超时离开时，要先把商品放回货架，放好后才释放预留。

## 表现层

| 模块 | 职责 |
|---|---|
| `view.ts` | 加载 GLB 并核对资产接口，摆放场景，在两个模拟步之间插值人物位置，处理点选、近看和场景标注。 |
| `camera.ts`、`room-cutaway.ts` | 全景和近看相机；视角转过去时自动隐藏挡住视线的墙。 |
| `first-person.ts` | 店员或顾客的第一视角跟随。 |
| `appearance.ts`、`expression-view.ts`、`emotions.ts` | 人物外观、表情，以及由模拟状态推出的心情（只用于显示）。 |
| `sound.ts` | 用 Web Audio 振荡器实时合成音效，只监听状态变化，不影响模拟。 |
| `game-shell.ts`、`*-ui.ts` | 顶部状态栏、底部功能入口和各个面板。 |
| `guided-tour.ts`、`guide-input.ts` | 新手引导：分步高亮可操作的控件，并拦截引导范围以外的点击。 |

表现层只读模拟状态，玩家操作通过 `sim.ts` / `day.ts` 提供的方法进入模拟。这样同一套规则既能在浏览器里玩，也能在 `tests/` 里无头运行。

## 存档

存档写在 localStorage 里，每个主题一个键。结构升级时，旧存档会先另存一份备份再迁移。「从头再来」只清空当前这三个主题的存档。

## 测试

```sh
npm test
```

测试覆盖账目守恒、预留与归还、补货调度、双收银台、布局与通道尺寸、营业日结算与重玩、新手引导状态等。其中一部分会直接读取 GLB 和规格文件，核对资产接口。所有测试都在 Node 里运行，不需要浏览器，也不需要 GPU。
